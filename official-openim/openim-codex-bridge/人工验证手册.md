# OpenIM Codex Bridge 人工验证手册

本文用于从 Phase 1 到当前 Phase 2C 验证 `openim-codex-bridge` 的功能是否正常。

当前已覆盖：

- Phase 1：OpenIM 单聊消息触发 bridge，调用 Codex CLI，并用 bot 回写 OpenIM
- Phase 2A：bindings、jobs、conversation status 查询
- Phase 2B：runtime job 取消
- Phase 2C：conversation rebind/archive 生命周期管理

本文默认在 Windows PowerShell 下执行，仓库根目录为：

```powershell
D:\agent_trial\claude_code\official-openim
```

## 1. 前置条件检查

预期：

- 命令能正常返回


`CODEX_DEFAULT_PROJECT_PATH` 必须是 Codex CLI 能访问的本地项目目录。

## 3. Phase 1 验证：最小闭环

Phase 1 验证目标：

```text
OpenIM user -> codex_bot -> webhook -> bridge -> Codex CLI -> OpenIM send_msg -> OpenIM client
```

### 3.1 使用 smoke 脚本验证

```powershell
cd D:\agent_trial\claude_code\official-openim
.\deploy\windows\smoke-e2e.ps1
```

预期输出：

```text
Smoke E2E succeeded.
```

并且最后的 JSON 中：

```json
{
  "status": "succeeded",
  "output_text": "SMOKE_ACK"
}
```

这说明：

- OpenIM `/msg/send_msg` 可用
- webhook 已触发 bridge
- bridge 成功创建 runtime job
- Codex CLI 被调用
- bridge 成功回写 bot 消息

### 3.2 使用 OpenIM 客户端手动验证

在 OpenIM 客户端中，用普通用户给 `codex_bot` 发送：

```text
请回复：HELLO_OPENIM_CODEX
```

预期：

- OpenIM 客户端收到 `codex_bot` 回复
- 回复中包含或准确返回 `HELLO_OPENIM_CODEX`
- bot 回复不会再次触发新一轮 Codex job

### 3.3 检查最新 job

```powershell
cd D:\agent_trial\claude_code\official-openim\openim-codex-bridge

node -e "const Database=require('better-sqlite3'); const db=new Database('data/openim-codex-bridge.sqlite'); console.log(db.prepare('select id,status,input_text,output_text,error_text from runtime_jobs order by rowid desc limit 1').get()); db.close();"
```

预期：

- `status` 为 `succeeded`
- `input_text` 是刚才发送给 bot 的文本
- `output_text` 有 Codex 输出
- `error_text` 为 `null`

## 5. Phase 2A 验证：状态查询 API

### 5.1 查询 bindings

```powershell
curl http://127.0.0.1:8787/api/bindings
```

预期返回：

```json
{
  "bindings": [
    {
      "openimConversationId": "single:codex_bot:bridge_user_1",
      "openimDisplayUserId": "bridge_user_1",
      "activeSessionRecordId": "...",
      "codexSessionId": "...",
      "codexProjectPath": "...",
      "sessionStatus": "active",
      "latestJobId": "...",
      "latestJobStatus": "succeeded"
    }
  ]
}
```

记录 conversation id：

```powershell
$conversationId = "single:codex_bot:bridge_user_1"
$cid = [uri]::EscapeDataString($conversationId)
```

### 5.2 查询单个 binding 详情

```powershell
curl "http://127.0.0.1:8787/api/bindings/$cid"
```

预期包含：

- `activeSession`
- `sessions`
- `activeJob`
- `latestJob`
- `recentJobs`

### 5.3 查询 conversation status

```powershell
curl "http://127.0.0.1:8787/api/conversations/$cid/status"
```

常见状态：

- `unknown`：没有 active session
- `idle`：有 active session，但当前无 active job
- `queued`：有排队 job
- `running`：有运行中 job
- `cancelling`：运行中 job 正在取消
- `completed`：最新 job 成功
- `failed`：最新 job 失败

如果最新 job 是 `cancelled` 且当前无 active job，conversation state 会返回 `idle`，客户端应查看 `latestJob.status` 展示取消结果。

### 5.4 查询单个 job

从 status 或 bindings 返回中拿到 `jobId`：

```powershell
$jobId = "<替换为实际 job id>"
curl "http://127.0.0.1:8787/api/jobs/$jobId"
```

预期包含：

- `status`
- `inputText`
- `outputText`
- `errorText`
- `codexSessionIdBefore`
- `codexSessionIdAfter`
- `cancelRequestedAt`
- `cancelledAt`
- `cancelMethod`

## 6. Phase 2B 验证：取消 Runtime Job

取消语义：

- 取消的是 bridge runtime job，不是 OpenIM conversation
- 不清空 active session
- 不自动回滚 Codex 已经修改的文件
- Windows 下最终用 `taskkill /PID <pid> /T /F` 结束 Codex 进程树

### 6.1 发起一个较长任务

在 OpenIM 客户端给 `codex_bot` 发送：

```text
请做一个较长的检查任务：扫描当前项目结构，阅读几个关键文件，然后再总结。执行前先详细检查，不要马上结束。
```

马上查询 status：

```powershell
curl "http://127.0.0.1:8787/api/conversations/$cid/status"
```

如果看到：

```json
{
  "activeJob": {
    "id": "job_xxx",
    "status": "running"
  }
}
```

记录 job id：

```powershell
$jobId = "job_xxx"
```

### 6.2 取消 running job

```powershell
curl -X POST "http://127.0.0.1:8787/api/jobs/$jobId/cancel"
```

预期：

- 返回 job
- `status` 可能是 `cancelling`
- `cancelMethod` 为 `api`

稍等几秒后：

```powershell
curl "http://127.0.0.1:8787/api/jobs/$jobId"
```

预期：

```json
{
  "status": "cancelled",
  "cancelMethod": "api"
}
```

OpenIM 客户端预期收到：

```text
Codex job was cancelled.
```

再查 conversation status：

```powershell
curl "http://127.0.0.1:8787/api/conversations/$cid/status"
```

预期：

- `state` 为 `idle`
- `latestJob.status` 为 `cancelled`
- `activeSession` 仍存在

### 6.3 取消 queued job

queued job 较难手动稳定制造。可以在一个长任务运行时，连续快速给 `codex_bot` 再发一条消息，第二条通常会进入 queued。

查询 recent jobs：

```powershell
curl "http://127.0.0.1:8787/api/conversations/$cid/status"
```

找到 `status = queued` 的 job，然后：

```powershell
$queuedJobId = "<queued job id>"
curl -X POST "http://127.0.0.1:8787/api/jobs/$queuedJobId/cancel"
curl "http://127.0.0.1:8787/api/jobs/$queuedJobId"
```

预期：

- queued job 直接变为 `cancelled`
- worker 后续会跳过该 job

### 6.4 取消 terminal job

对一个已经 `succeeded` 或 `failed` 的 job 执行：

```powershell
curl -X POST "http://127.0.0.1:8787/api/jobs/$jobId/cancel"
```

预期：

- 返回当前 job
- 状态不变化
- 不会新增 OpenIM 回复

## 7. Phase 2C 验证：Rebind 和 Archive

### 7.1 Rebind 到新的空 Codex session

推荐先不传 `codexSessionId`，让下一条消息创建新的 Codex session：

```powershell
curl -X POST "http://127.0.0.1:8787/api/bindings/$cid/rebind" `
  -H "content-type: application/json" `
  -d '{"codexProjectPath":"D:/agent_trial/claude_code/official-openim"}'
```

预期：

- HTTP 201
- 返回新的 `activeSession`
- `activeSession.createdReason` 为 `manual_rebind`
- `activeSession.codexSessionId` 为 `null`
- 旧 session 仍在 `sessions` 中，但 `isActive = false`

验证：

```powershell
curl "http://127.0.0.1:8787/api/bindings/$cid"
```

然后在 OpenIM 客户端给 `codex_bot` 发：

```text
请回复：REBIND_OK
```

预期：

- job 成功
- 新 active session 被写入新的 `codexSessionId`

### 7.2 Rebind 到指定 Codex session id

只有在你确认 session id 有效时才建议执行。

```powershell
curl -X POST "http://127.0.0.1:8787/api/bindings/$cid/rebind" `
  -H "content-type: application/json" `
  -d '{"codexProjectPath":"D:/agent_trial/claude_code/official-openim","codexSessionId":"<已有有效 Codex session id>"}'
```

预期：

- HTTP 201
- `activeSession.codexSessionId` 为你传入的 id
- 下一条消息会尝试 `codex exec resume <sessionId> --json`

注意：

- 如果传入假的 `codexSessionId`，下一次 Codex resume 可能失败
- 测试后可再次执行不带 `codexSessionId` 的 rebind 恢复为空 session

### 7.3 Archive 当前 binding

```powershell
curl -X POST "http://127.0.0.1:8787/api/bindings/$cid/archive"
```

预期：

- HTTP 200
- `archivedSession.status` 为 `archived`
- `archivedSession.isActive` 为 `false`
- `activeSession` 为 `null`

查询 status：

```powershell
curl "http://127.0.0.1:8787/api/conversations/$cid/status"
```

预期：

```json
{
  "state": "unknown",
  "activeSession": null
}
```

然后在 OpenIM 客户端再发一条消息给 `codex_bot`：

```text
请回复：ARCHIVE_NEW_SESSION_OK
```

预期：

- bridge 自动创建新的 active session
- OpenIM 收到 bot 回复
- 查询 bindings 时能看到新的 `activeSessionRecordId`

### 7.4 active job 期间禁止 rebind/archive

先发起一个长任务，让 status 中出现 active job：

```powershell
curl "http://127.0.0.1:8787/api/conversations/$cid/status"
```

确认 `activeJob.status` 是 `queued`、`running` 或 `cancelling` 后执行：

```powershell
curl -X POST "http://127.0.0.1:8787/api/bindings/$cid/archive"
```

以及：

```powershell
curl -X POST "http://127.0.0.1:8787/api/bindings/$cid/rebind" `
  -H "content-type: application/json" `
  -d '{"codexProjectPath":"D:/agent_trial/claude_code/official-openim"}'
```

预期：

- HTTP 409
- 返回中包含：

```json
{
  "error": "active job exists"
}
```

## 8. 数据库人工检查

进入 bridge 目录：

```powershell
cd D:\agent_trial\claude_code\official-openim\openim-codex-bridge
```

### 8.1 查看最近 jobs

```powershell
node -e "const Database=require('better-sqlite3'); const db=new Database('data/openim-codex-bridge.sqlite'); console.table(db.prepare('select id,status,input_text,codex_session_id_before,codex_session_id_after,cancel_method,error_text from runtime_jobs order by rowid desc limit 10').all()); db.close();"
```

重点看：

- cancelled job 有 `cancel_method`
- failed job 有 `error_text`

### 8.2 查看 session records

```powershell
node -e "const Database=require('better-sqlite3'); const db=new Database('data/openim-codex-bridge.sqlite'); console.table(db.prepare('select id,openim_conversation_id,codex_session_id,codex_project_path,is_active,status,parent_session_record_id,forked_from_codex_session_id,created_reason from codex_session_records order by rowid desc limit 20').all()); db.close();"
```

重点看：

- 同一 conversation 只有一条 `is_active = 1`
- archive 后当前 session `status = archived` 且 `is_active = 0`
- rebind 后新 session `created_reason = manual_rebind`
- rebind 新 session 的 `parent_session_record_id` 指向旧 active session

### 10.3 Codex job failed

```powershell
cd D:\agent_trial\claude_code\official-openim\openim-codex-bridge
```

```powershell
codex exec --cd D:\agent_trial\claude_code\official-openim --json -
```

然后输入一个简单 prompt 后结束 stdin。

### 10.4 bot 回复触发回环

检查 bot 回写消息的 `ex` 是否包含：

```json
{
  "agent": {
    "generated_by": "codex"
  }
}
```

当前 bridge 的 `OpenImMessageSender` 会自动写入该字段。若仍回环，检查 OpenIM webhook payload 中 `ex` 是否被正常传回。

## 11. 建议验收顺序

推荐按下面顺序完整跑一遍：

1. `docker compose up -d`
2. `bootstrap-openim-bridge.ps1`
3. `npm run build`
4. `stop-bridge.ps1`
5. `start-bridge.ps1`
6. `curl /healthz`
7. `smoke-e2e.ps1`
8. OpenIM 客户端手动给 `codex_bot` 发消息
9. `GET /api/bindings`
10. `GET /api/conversations/:conversationId/status`
11. 发长任务并 `POST /api/jobs/:jobId/cancel`
12. `POST /api/bindings/:conversationId/rebind`
13. OpenIM 再发消息验证新 session
14. `POST /api/bindings/:conversationId/archive`
15. OpenIM 再发消息验证自动创建新 active session

完成以上步骤即可认为 Phase 1 到 Phase 2C 的人工验证通过。
